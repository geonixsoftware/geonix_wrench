OPEN FINDINGS
================================================================================

--------------------------------------------------------------------------------
1. HIGH - Wildcard CORS combined with credentials
FIXED 2026-08-15: main.py now reads ALLOWED_ORIGINS (comma-separated) from
the environment and, when set, allows only those origins with credentials and
an explicit method/header list. With it unset the API falls back to any origin
WITHOUT credentials and logs a startup warning, so local development still
works but the credentialed wildcard is gone.
ACTION STILL NEEDED: set ALLOWED_ORIGINS in the deployed environment.

--------------------------------------------------------------------------------
Original finding:
--------------------------------------------------------------------------------
Evidence: geonix_wrench_backend/main.py:73-78
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],

Risk: with allow_credentials=True, Starlette does not send a literal "*";
it echoes the requesting Origin back and sets
Access-Control-Allow-Credentials: true. The practical effect is that ANY
website can make cross-origin requests to this API and read the responses.
Authentication is Bearer-token based rather than cookie based, which limits
classic CSRF, but any page that obtains a token can drive the whole API from
a browser, and every endpoint's response body is readable cross-origin.

Remediation: drive allow_origins from an ALLOWED_ORIGINS env var listing the
real app/site origins. Keep the wildcard for local development only, and do
not pair it with allow_credentials=True.

--------------------------------------------------------------------------------
2. HIGH - Live SQLite database committed, containing real user data
PARTLY FIXED 2026-08-15: geonix_wrench.db is untracked (git rm --cached) and
*.db / *.sqlite3 are in .gitignore. The file itself is untouched on disk.
ACTION STILL NEEDED: the blob remains in the two existing commits. Purge it
with git filter-repo or BFG before the repo is shared. I did not rewrite
history unprompted - it is destructive and this repo has no remote to recover
from.

--------------------------------------------------------------------------------
Original finding:
--------------------------------------------------------------------------------
Evidence: geonix_wrench_backend/geonix_wrench.db is tracked
(`git ls-files` lists it). Reading the committed blob at HEAD:
    users            1 row
      columns: id, firebase_uid, email, handle, display_name, org_id,
               org_role, created_at
      contains a real firebase_uid, a real email address and the handle

Risk: personal data and a Firebase UID are in version control, and will be
in every clone and every future copy of the history. If this repository is
ever published the data is public permanently. A Firebase UID is also the
subject identifier used for auth, so it is not merely cosmetic.

Remediation: `git rm --cached geonix_wrench_backend/geonix_wrench.db`, add
*.db / geonix_wrench.db to .gitignore, and purge it from history
(git filter-repo or BFG) before the repo is shared. Ship an empty schema and
create the database at first run instead.

3. MEDIUM - Unbounded audio upload read fully into memory
FIXED 2026-08-15: limits.read_upload_capped() streams the body to disk in
1 MB chunks under MAX_AUDIO_SIZE_BYTES (default 25 MB), rejects an oversized
Content-Length before reading anything, and still enforces the cap while
streaming because that header is client-supplied. Covered by tests in
tests/test_limits.py.

--------------------------------------------------------------------------------
Original finding:
--------------------------------------------------------------------------------
Evidence: geonix_wrench_backend/main.py:145-147
    with tempfile.NamedTemporaryFile(suffix=ext, delete=False) as tmp:
        tmp.write(await file.read())

Only the file extension is checked (main.py:141-143). There is no
MAX_AUDIO_SIZE, no Content-Length check, and no streaming: the entire body is
buffered in memory before anything else happens.

Risk: a single authenticated caller can exhaust server memory with one large
request. Transcription then runs Whisper over whatever arrives, multiplying
the cost. This is the cheapest denial-of-service path in the codebase.

Remediation: add MAX_AUDIO_SIZE_BYTES to config, reject on Content-Length
before reading, stream to disk in chunks with a running byte cap, and abort
once the cap is passed. Enforce a body-size limit at the ASGI server too.

--------------------------------------------------------------------------------
4. MEDIUM - Logo upload is size-checked only after buffering
FIXED 2026-08-15: the logo path uses the same capped reader, so an oversized
upload is refused without being buffered whole.

--------------------------------------------------------------------------------
Original finding:
--------------------------------------------------------------------------------
Evidence: geonix_wrench_backend/main.py:221-223
    data = await file.read()
    if len(data) > MAX_LOGO_SIZE_BYTES:
        raise HTTPException(status_code=400, detail="Logo file is too large")

The limit exists (5 MB) but is applied after the whole body is already in
memory, so an oversized upload still costs full memory before rejection.

Remediation: check Content-Length first and read in bounded chunks.

--------------------------------------------------------------------------------
5. MEDIUM - No rate limiting anywhere
FIXED 2026-08-15: limits.enforce_rate_limit() applies a per-user fixed
window. /api/process-audio gets its own tighter budget
(RATE_LIMIT_AUDIO_PER_WINDOW, default 10/min) because it runs Whisper and
calls a paid model. Counters are per-process: if this is ever run with more
than one worker, move them to Redis or each worker grants the full budget.

--------------------------------------------------------------------------------
Original finding:
--------------------------------------------------------------------------------
Evidence: no slowapi/limiter/rate-limit usage anywhere in
geonix_wrench_backend/*.py.

Risk: /api/process-audio calls a paid LLM and runs Whisper; /api/auth/handle
allows handle enumeration; /api/billing/* touches Stripe. None are throttled,
so cost and abuse scale with whatever an authenticated client chooses to send.

Remediation: per-user and per-IP limits, tightest on /api/process-audio.

--------------------------------------------------------------------------------
6. MEDIUM - Interactive API docs and schema are public
FIXED 2026-08-15: docs_url, redoc_url and openapi_url are None unless
ENABLE_API_DOCS=true.

--------------------------------------------------------------------------------
Original finding:
--------------------------------------------------------------------------------
Evidence: geonix_wrench_backend/main.py:70
    app = FastAPI(title="Geonix Wrench API")
docs_url / redoc_url / openapi_url are not set, so FastAPI serves /docs,
/redoc and /openapi.json to anyone, unauthenticated.

Risk: publishes the full route map, parameter names and schemas to attackers.
Not a vulnerability on its own; it removes all guesswork from finding one.

Remediation: disable in production (docs_url=None, redoc_url=None,
openapi_url=None) or gate them behind auth, driven by an env flag.

--------------------------------------------------------------------------------
7. MEDIUM - No length limits on text reaching the PDF generator or the LLM
FIXED 2026-08-15: extract_jobcard() truncates the transcript to
MAX_TRANSCRIPT_CHARS (20k) before it reaches either provider and logs when it
does. pdf_generator._clip() bounds each field to MAX_FIELD_CHARS, strips
control characters, and the parts table is capped at MAX_PARTS_PER_JOBCARD.

--------------------------------------------------------------------------------
Original finding:
--------------------------------------------------------------------------------
Evidence: no truncation, max_length or slicing in
geonix_wrench_backend/pdf_generator.py or extraction.py. extract_jobcard()
takes the transcript verbatim (extraction.py:63), and job card fields are
passed straight into reportlab Paragraph objects.

Risk: unbounded strings inflate LLM cost and can break or hang PDF rendering.
Transcript text also lands in the prompt unmodified, so prompt injection can
influence extraction. Pydantic validates the shape of the result, which
limits the blast radius, but not the content.

Remediation: cap transcript length before the prompt; cap field lengths and
the parts-list size before rendering; strip control characters.

--------------------------------------------------------------------------------
On 2026-08-14 a live STRIPE_API_KEY (sk_live_), a STRIPE_WEBHOOK_SECRET

9. LOW - Firebase web config remains in public repo history
--------------------------------------------------------------------------------
Evidence: github.com/geonixsoftware/geonix is public (GitHub API reports
"private": false). assets/firebase-config.js was added in commit 38f2b82 and
removed in 8263579, so it stays reachable in history.

Risk: low by design. A Firebase web apiKey is a public identifier, not a
secret; it ships in every web and app build. Security depends on Firebase
security rules and the Authorized Domains list, not on hiding this value.

Remediation: none required. Do confirm Authorized Domains is restricted to
domains you control, and that Firestore/Storage rules are not permissive.

================================================================================
CHECKED AND FOUND SOUND
================================================================================

- Authentication coverage: every route except POST /api/billing/webhook
  requires Depends(get_current_user). The webhook is correctly unauthenticated
  and instead verified with stripe.Webhook.construct_event against
  STRIPE_WEBHOOK_SECRET (billing.py).
  NOTE: an earlier pass of this audit flagged POST /api/process-audio and
  POST /api/shop-logo as unauthenticated. That was a false positive caused by
  a pattern that did not span their multi-line signatures. Both do take
  user: dict = Depends(get_current_user) (main.py:139 and main.py:215).

- SQL injection: none found. Every statement in database.py uses "?"
  placeholders; no f-string or concatenated SQL.

- Authorization on seat changes: billing.update_team_seats() checks org
  membership, owner role, plan minimum, and refuses to drop below the number
  of seats actually occupied.

- No hardcoded secrets in the Flutter app source.

- Verbose auth error text is gated behind kDebugMode
  (auth_exceptions.dart:21, 75, 107), so release builds do not leak codes.

- Local file encryption keys are held in flutter_secure_storage
  (file_cipher.dart:23), i.e. Keychain/Keystore rather than plaintext.
